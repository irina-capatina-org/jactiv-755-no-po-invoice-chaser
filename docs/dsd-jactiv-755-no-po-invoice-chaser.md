## 1. Solution Overview

Weekday unattended control that queries Coupa for invoices in `draft` or `new` status dated within the last 7 days, excludes credit notes and invoices with a linked PO, and posts a Slack Block Kit DM to the AP SME when qualifying invoices are found. Silent on a clean day. No Coupa records are modified.

| Project | Role | Entry point |
|---|---|---|
| `no-po-invoice-chaser-api` | Primary (only) | Schedule-triggered API Workflow |

## 2. As-Built Architecture

```
Orchestrator schedule (weekday, 10:00 Europe/Bucharest)
        |
        v
no-po-invoice-chaser-api  [Workflow.json]
        |
        +--[GET invoices]--> Coupa  (connector: uipath-coupa-coupa)
        |
        +--[POST chat.postMessage]--> Slack  (connector: uipath-salesforce-slack)
           (only when qualifyingCount > 0)
```

Single sequence; no sub-workflows. Both external calls use the UiPath HTTP connector (`uipath-uipath-http`) proxying through the named Integration Service connections. No queues, no assets, no packages.

SDD specified a Try/Catch wrapper — the delivered workflow has no explicit Try/Catch node; unhandled exceptions propagate to the Orchestrator job runner which marks the job failed.

## 4. Exception and Error Handling

No retry is implemented (BR-08). Any unhandled exception marks the job failed and writes a stack trace to the Orchestrator job log. Business exceptions B1–B3 are filter predicates inside `Javascript_FilterAndCount`, not error branches.

| ID | Failure | Detected at | Result |
|---|---|---|---|
| S1 | Coupa query failure (HTTP non-2xx or exception) | `HTTP_Request_Coupa` | Job failed; logged |
| S2 | Slack delivery failure (`ok !== true`) | `Javascript_ValidateSlack` (throws) | Job failed; logged |
| S3 | Endpoint unreachable / timeout | `HTTP_Request_Coupa` or `HTTP_Request_Slack` | Job failed; logged |
| S4 | Credential / binding error | Integration Service layer | Job failed; logged |
| S5 | Unhandled runtime exception | Orchestrator job runner | Job failed; stack trace logged |
| B1 | Credit note (`invoice-type === 'Credit Note'`) | `Javascript_FilterAndCount` | Excluded from count; added to `exclusionLog` |
| B2 | Description-only PO (`po-number` and `order-header-num` empty on all lines) | `Javascript_FilterAndCount` | Counted as qualifying (BR-02) |
| B3 | Clean day (`qualifyingCount = 0`) | `If_1` branch | Slack skipped; job succeeds; `slack_sent = false` |

## 5. Operations Runbook

**Trigger:** Orchestrator schedule — weekday, 10:00 `Europe/Bucharest`. No input arguments.

**Manual run:** Open the process in Orchestrator → Start Job → no arguments required.

**Expected runtime:** Under 30 seconds. Volume: up to 50 invoices per run (hard `limit=50`).

**Normal log output** (from `Javascript_LogResult`):
```
qualifying_count=<n>
slack_sent=<true|false>
```

**Normal job output:** `{ status: "Successful", qualifying_count: <n>, slack_sent: <bool> }`
